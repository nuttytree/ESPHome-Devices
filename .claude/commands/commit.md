---
description: Run pre-commit hooks to a clean state, commit the staged/modified changes, and push.
---

Get the working tree to a committable state, commit it, and push it.

1. Check the current branch (`git branch --show-current`). If it's `master`, create and switch to a new feature branch before doing anything else — don't commit on `master` (the `no-commit-to-branch` hook blocks it anyway). Name the branch from what's actually changing, following this repo's convention: `f/<short-kebab-case-description>` for a feature/change, `b/<short-kebab-case-description>` for a bug fix, `chore/<short-kebab-case-description>` for maintenance/tooling (see existing branches for examples). Base it off the pending changes (`git status`/`git diff`), not off the eventual commit message wording verbatim.
2. Run `pre-commit run --all-files`. pre-commit is installed via pipx and shimmed at `~/.local/bin/pre-commit`, so the bare command works; `python -m pre_commit` does **not** — the `python` on `PATH` has no `pre_commit` module. If a hook modifies files (e.g. `ruff-format`), `git add` those files and re-run until every hook reports `Passed`. If a hook fails for a reason it can't auto-fix (e.g. `flake8`), stop and report the failure instead of committing — don't work around it with `--no-verify`.
3. Once hooks are clean, follow the normal commit workflow: review `git status` and `git diff --cached` (and unstaged changes, staging anything that belongs in this commit) for what's about to be committed, check `git log --oneline -10` for this repo's message style, draft a concise commit message focused on *why*, then create the commit with the `Co-Authored-By: Claude <noreply@anthropic.com>` trailer as usual, and confirm with `git status` afterward.
4. Push the branch: `git push`, or `git push -u origin <branch>` if it has no upstream yet (a brand-new feature branch created in step 1 won't). `push.followTags` is already configured locally, so any version tag the `tag-esphome-version` post-commit hook created will be pushed along with it automatically — no separate tag push needed. If the push is rejected (e.g. remote has diverged), stop and report it rather than force-pushing.
5. Never skip hooks.
